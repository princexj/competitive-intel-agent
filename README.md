# SignalForge Competitive Intelligence

SignalForge is an evidence-backed competitive intelligence workbench. Research one
company or compare up to four targets across live market activity, technical
research, and practitioner sentiment.

## Why v2 is different

- Typed LangGraph state replaces model-text routing and exact prefix matching.
- Market, academic, and community research run as parallel graph branches.
- Every finding retains its URL, publisher, date, category, and source snippet.
- The UI shows real workflow events instead of simulated timestamps.
- Multi-target runs produce a side-by-side strategic comparison.
- Reports and source ledgers are saved to local SQLite history.
- Markdown and JSON exports make the result useful outside Streamlit.
- Network boundaries are isolated so the workflow can be tested offline.

## Workflow

```text
                         +--> Market research -----+
Target -> Research plan -+--> Technical research --+-> Analyst -> Cited report
                         +--> Community research --+

Multiple target reports -> Comparison analyst -> Competitive landscape
```

The graph's nodes read and write a shared `IntelState`. Research branches update
separate fields and join at the analyst, so routing does not depend on phrases
generated by the model.

## Stack

| Layer | Technology |
| --- | --- |
| Workflow | LangGraph 1.2+ |
| LLM | Llama 3.3 70B through Groq |
| Market search | Tavily |
| Academic search | arXiv and Semantic Scholar |
| Product UI | Streamlit |
| History | SQLite |
| Cache | Structured JSON, 24-hour TTL |

## Setup

Requires Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
```

You can enter keys in the Streamlit sidebar or set environment variables:

```text
GROQ_API_KEY=...
TAVILY_API_KEY=...
```

Keys entered in the UI remain in Streamlit session memory. They are not written to
the report database or search cache.

## Run

```bash
streamlit run app.py
```

For the CLI:

```bash
python main.py "Anthropic" "OpenAI" "Mistral AI"
```

The CLI accepts `--output`, `--groq-key`, and `--tavily-key`.

## Project structure

```text
app.py        Streamlit workbench and live workflow display
graph.py      LangGraph nodes, edges, streaming, and comparison
state.py      Typed workflow and source contracts
tools.py      Structured Tavily, arXiv, and Semantic Scholar clients
llm.py        Minimal Groq chat client with JSON parsing
storage.py    SQLite report history
main.py       CLI entry point
tests/        Offline unit and workflow tests
```

Generated caches and report history live under `.cache/` and are ignored by Git.
The root-level `cache.json` is a legacy v1 artifact and is no longer used.

## Verification

```bash
python -m unittest discover -s tests -v
python -m compileall -q .
```

The automated suite does not call paid APIs. A complete live report still requires
valid Groq and Tavily keys.

## Honest limitations

- Scores are analyst-model judgments, not audited financial metrics.
- Community search is restricted to a handful of practitioner-heavy domains.
- Citation formatting is prompted and source-bounded, but reports should still be
  reviewed before high-stakes decisions.
- Runs execute targets sequentially to keep API usage and rate-limit behavior
  predictable; research branches inside each target run in parallel.
